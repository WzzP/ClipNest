<h1 align="center">ClipNest · 剪贴巢</h1>

<p align="center">复制过的文字、图片和文件，随时找回来。</p>

ClipNest 是一个原生 macOS 剪贴板管理工具。平时常驻菜单栏，按 **⌘⇧V** 唤出屏幕底部的历史卡片栏，搜索、预览，再复制或粘贴到原来的应用。

使用 **SwiftUI + AppKit** 构建，无需账号，历史保存在本机。当前版本为 **0.1.1**。

## 功能

- **多种内容**：记录文本、链接、图片，以及 Finder 中复制的单个或多个文件。
- **快捷操作**：全局快捷键唤出，键盘选择，单击选中、双击粘贴。
- **搜索与收藏**：按内容、文件名或来源应用搜索；收藏常用片段。
- **图片预览**：卡片缩略图、展开预览，后台加载并缓存缩略图。
- **本地历史**：去重、持久化，普通历史数量可选 50 / 200 / 500 / 1,000 条；收藏不计入上限。
- **记录控制**：暂停记录、排除指定应用、跳过常见敏感剪贴板标记。
- **登录启动**：可在设置中开启，登录 macOS 后在后台运行。

## 构建与运行

需要 **macOS 14 或更新版本**、**Swift 6 工具链**。可安装 Xcode，或安装包含兼容 Swift 版本的 Command Line Tools。

```sh
git clone https://github.com/WzzP/ClipNest.git
cd ClipNest
./scripts/build-app.sh
open .build/sandbox/ClipNest.app
```

脚本编译 Release 版本、生成应用图标，并打包为 `.build/sandbox/ClipNest.app`。默认使用本地临时签名，**没有 Developer ID 发布签名，尚未公证**。

日常使用建议将生成的 `ClipNest.app` 放到“应用程序”目录，再从那里启动，并保持应用路径固定。不要同时运行多个副本，以免快捷键冲突。

仅调试源码时也可以直接运行（不启用沙盒，不能替代打包验证）：

```sh
swift run ClipNest
```

登录启动需要运行打包后的 `.app`。静默启动可使用：

```sh
open .build/sandbox/ClipNest.app --args --background
```

## 使用方式

复制内容后，点击菜单栏剪贴板图标，或按 **⌘⇧V** 打开历史。正常启动、再次双击应用也会显示面板。

| 操作 | 行为 |
| --- | --- |
| 输入关键词 | 搜索内容和来源应用 |
| 单击卡片 | 立即选中 |
| ↑ / ↓ | 切换选中条目 |
| ← / → | 离开搜索输入框后切换条目 |
| 空格 | 离开搜索输入框后切换预览 |
| Enter / 双击卡片 | 向原应用发送粘贴指令 |
| 点击“复制” | 写入系统剪贴板，随后自行按 ⌘V 粘贴 |
| 点击星标 | 收藏或取消收藏 |
| 右键卡片 | 复制、收藏、删除 |
| Esc | 先关闭预览，再关闭面板 |

使用中文输入法时，候选词确认、方向键选词和取消组合优先交给输入法；结束组合后才处理历史快捷键。

齿轮按钮打开设置，可调整保存数量、暂停记录、设置排除应用、管理登录启动，以及清空普通历史。清空历史会保留收藏；单条删除需要确认。

## 权限

**剪贴板读取**与**辅助功能**是两种不同的系统权限。

- **读取剪贴板**：系统限制访问时，底栏会提示原因。允许访问后，可点击“读取当前剪贴板”重试。
- **自动粘贴**：需要在“系统设置 → 隐私与安全性 → 辅助功能”中允许当前 ClipNest。仅使用“复制”按钮不需要辅助功能权限。
- **登录启动**：在“设置 → 常规”中开启。如果系统需要进一步允许，应用会提供“打开登录项设置”入口。

### 已授权，为什么更新后仍提示未授权？

默认的 ad-hoc 临时签名绑定具体构建，修改代码重新打包后，旧辅助功能授权可能不再匹配。可在系统设置中移除旧条目，再添加当前 `.app`、开启权限并重启。应用设置提供“重新检查”和“在 Finder 中显示当前应用”入口。

如果已安装代码签名证书，可在后续构建中保持同一签名身份：

```sh
CLIPNEST_SIGN_IDENTITY="证书名称或指纹" ./scripts/build-app.sh
```

构建脚本不会创建证书或修改系统权限。移动应用或清理 `.build` 后，也应检查登录启动设置是否仍有效。

## 数据如何保存

数据目录：

```text
~/Library/Containers/com.clipnest.sandbox/Data/Library/Application Support/ClipNest/
├── history.json     # 内容、来源、收藏及文件路径
└── Attachments/     # 图片原始数据
```

- **文本和图片**保存到本地，重启后恢复。图片作为独立附件保存，不内嵌到历史 JSON。
- **文件记录保存原路径，不备份原文件**。Finder 中复制的图片文件也按文件处理。原文件被移动、删除或临时目录被清理后，记录会无法再次复制；应用会提示并保留当前剪贴板。
- 删除或淘汰历史时，清理不再使用的图片附件；**不会删除原文件**。
- 历史为本机明文数据，文件权限限制为当前用户读写。敏感标记过滤依赖来源应用，不能识别所有密码；可通过应用 Bundle ID 配置排除列表。
- 历史文件无法解析时停止覆盖并显示错误。备份时请保留整个数据目录。

0.1.1 启用 App Sandbox，应用名称仍为 ClipNest。旧版本位于 `~/Library/Application Support/ClipNest/` 的历史不会自动迁移，也不会被删除。自动粘贴和外部文件跨重启权限尚未完整验证；可先用“复制”后手动按 ⌘V。快捷键被占用时自动改用 **⌃⌘⇧V**，实际组合见菜单栏提示。

## 当前限制

- 每 0.35 秒检查一次剪贴板，极短时间内连续复制可能只捕获最后一条。
- 不记录空白文本；单条文本上限 1 MB，图片上限 25 MB、1 亿像素。
- 图片支持 PNG、TIFF、JPEG、HEIC；暂不提供完整动画预览。
- 不支持尚未落盘的文件承诺、富文本格式保留、云同步、自定义分组、可配置全局快捷键及删除撤销。
- 自动粘贴会检查目标应用并发送 ⌘V，但无法确认每个第三方应用是否实际接受内容。
- 图片缩略图已在后台加载；历史写入、剪贴板内容读取和部分复制操作仍同步执行，大文件场景仍有优化空间。

## 开发与验证

```sh
swift build
./scripts/test.sh
./scripts/test-sandbox.sh
```

测试脚本可在 Command Line Tools 环境运行，无需 XCTest。包含 12 项历史行为检查，以及后台缩略图生成、缓存、缺失附件与输入法按键路由检查；使用隔离数据目录与命名剪贴板，不修改系统通用剪贴板。

```text
Sources/ClipNest/
├── AppDelegate.swift        # 菜单栏、底部面板、全局快捷键与自动粘贴
├── ClipNestApp.swift        # 应用入口
├── HistoryStore.swift       # 剪贴板捕获、数据模型与本地存储
├── HistoryView.swift        # 历史卡片、预览与设置
├── KeyboardRouting.swift    # 输入法组合与历史快捷键分流
├── LoginItemSettings.swift  # 系统登录项管理
└── ThumbnailLoader.swift    # 后台缩略图加载与缓存
```

设计演进记录见 [产品形态草案](docs/design/product-shape.md)。
